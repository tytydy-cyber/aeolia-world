# AEOLIA 動作・性能・ユーザビリティ検査

## 修正後の結果（2026-09-16）

下記の初回検査で挙げた4件を修正し、回帰テストを実行した。

- 塔・風車：円形の衝突判定を追加。外壁で停止し、屋根より高い位置なら飛び越えられる。屋根を含む判定は保守的な円柱近似で、斜面の形状には厳密に沿わない。
- 橋：橋面より下の飛行、下面への頭の衝突、上からの着地、3本の橋の上り歩行が合格。高さ10で橋の下を横断しても上へ移されない。
- 設定：マウスで消音・移動エフェクト・音量・速度を操作した後、ゲーム画面へフォーカスを戻す。キーボードではスライダーの標準操作を保ち、Escでゲームへ戻る。設定に入る際は押下中の移動キーを解除する。
- 時間処理：5/10/15/20/30/60/120fps相当の1秒移動距離は8.221〜8.230、差は約0.12%以内。エフェクトも経過時間を保持する。250msを超える単発停止とウィンドウ復帰は停止時間として扱い、大きな移動を防ぐ。
- Ctrl加速とEsc設定終了を画面の操作ガイドに追記。

操作テストの代替DOMも、要素ごとのイベント登録・フォーカスを扱うよう修正した。ただし実ブラウザでの入力検証とは区別する。

再計測したCPU時間（各1,500回、同じ条件）：停止 中央値0.475ms / p95 0.525ms、歩行0.510ms / 0.563ms、飛行0.459ms / 0.509ms。音・エフェクトの更新を移動と同じ細かい時間刻みに揃えたため、前回より処理時間は増えている。GPU時間は含まない。描画オブジェクト数は変更していない。

`node work/audit-game.mjs`、`node work/test-audio.mjs`、`node work/test-effects.mjs` はすべて合格。audit-game の期待値は修正後の挙動に更新した。HTTPで配信中のHTMLと保存ファイルの一致も確認済み。

### 実ブラウザ確認（追試）

Codex内ブラウザの639×709表示で実際にページを開き、WebGL描画、開始操作、設定操作後のCanvasへのフォーカス復帰、十字キー入力、HUD配置を確認した。

- 当初の開始地点ではカメラが樹冠に入り、位置変更後も段丘の壁が画面の大部分を占めた。開始地点を(-25,3,5)、カメラを(-25,9,14)へ移動し、中央市場・建物・樹木・屋台・ベンチが最初から見える構図に修正した。
- 消音ボタン操作後、フォーカスがCanvasへ戻ることを実ブラウザで確認した。十字キー入力でキャラクターの歩行姿勢と位置が変化することも確認した。
- Three.js 0.186で廃止済みのPCFSoftShadowMap警告を確認し、PCFShadowMapへ変更した。変更後の新規読込では同じ設定を使わない。
- テクスチャ、影、キャラクター、建物、小物、HUDは実WebGLで描画された。639px幅では左右の操作UIは重ならなかったが、下部の操作ガイドは密度が高い。
- 実ブラウザ内でのフレーム間隔の自動採取はタイムアウトしたため、FPS値は未計測。目視のみを性能数値として扱わない。

### 実GPU計測と調整（追試2）

ゲーム自身のrequestAnimationFrame時刻とThree.jsの描画統計を使う計測表示を追加した。通常は非表示で、URLに `debug=1` がある場合だけ2秒単位でFPS・p95フレーム時間・描画回数・三角形数を表示する。

Codex内ブラウザ、639×709 CSSピクセルで測定した結果：

| 条件 | FPS | p95 | 描画回数 | 三角形 |
|---|---:|---:|---:|---:|
| 調整前・停止 | 60.0 | 17.7ms | 840 | 577,318 |
| 調整前・飛行 | 47.0 | 33.4ms | 888 | 604,070 |
| 調整後・停止 | 60.0 | 17.6ms | 838 | 577,314 |
| 調整後・飛行 | 60.0 | 17.8ms | 877 | 607,522 |

調整内容はデバイスピクセル比の上限を2から1.5、影マップを2048角から1024角へ変更したこと。飛行時の表示更新は60fpsへ回復した。シーン内容、テクスチャ、小物、影の有無は維持している。描画回数自体は多いため、低性能GPUや高解像度画面での結果は別途確認が必要。

### 音声の技術検査

環境風、石・木の足音、飛行風、発見チャイムについて、開始ジェスチャー、停止・再開、消音、音量、発音数上限、発音終了後の解放を再検査し、すべて合格した。全音声をネイティブのダイナミクスコンプレッサーへ通し、音が重なった場合のクリッピングを抑えるようにした。既定音量35%では、環境風・単一足音・チャイムの設定ゲインの合計にも余裕がある。

物理的なスピーカーや聴覚による音色の好みは自動検査できない。この点は不具合の残件ではなく、公開前の官能評価項目として扱う。

### 生成2D遠景の試作

生成画像を使った多層背景を追加した。遠景は2048×1024のパノラマ、中景はアルファ付きPNGを左右に分けた2枚のスプライト、近景は既存3Dで構成。中景だけをゆっくり上下・明滅させ、カメラからの距離差で視差を作る。追加は2描画、2スプライトで、影や衝突判定は増やしていない。

実ブラウザの飛行時は60.0fps、p95 17.6ms、908 calls、約61.2万三角形。FPS低下は確認されなかった。地上では建物が遠景を適度に隠し、高度を上げると環状遺跡と浮遊都市が現れる。背景素材と生成指示は `assets/textures/GENERATED-ASSETS.md` に記録した。

### カメラと手すりの追試

- 左・右どちらのドラッグでも視点を操作できる。ドラッグしていないマウス移動には反応しない。上下範囲は pitch -0.55〜1.15とし、生成パノラマの極端な上下端と地形裏面を出さず、上空・足元を見られる範囲に限定した。
- 移動は従来どおりカメラ基準。カメラの自動追従は追加せず、Cを押した場合だけ最後の実移動方向と標準仰角へ滑らかに復帰する。
- 移動前のCで180度反転する初期不具合を実ブラウザ確認で発見し、キャラクターの回転値ではなく最後の実移動方向を記録する方式へ修正した。
- 橋の手すりは各支柱の前後2.5区間の橋面高から角度を計算し、曲線と勾配に沿わせた。20本以上が水平固定ではないことを自動検査した。
- 通常表示で60.0fps、p95 16.8ms。新規のコンソールエラー・警告なし。

### 残タスクと次の行動

別のGPU環境と人による官能評価は未確認。公開前に以下を検証する。

1. スピーカーまたはヘッドホンで環境音・足音・飛行音・発見音の音量差と継ぎ目を確認する。
2. 市場から塔へ飛び、橋の下を通る一連の経路を人が操作して、カメラ酔い・橋付近の視認性・操作感を評価する。
3. 対象にする最低性能の端末が決まった時点で、同じ `debug=1` 計測をその端末で行う。60fpsを維持できなければ、橋・木の描画集約と影を落とす対象の削減を次に行う。

## 判定

基本機能のロジックテストは合格。ただし衝突判定・キー操作・低フレームレート時の速度に問題があり、快適性の合格判定は保留。

本番コードは変更していない。追加検査は Node 上で実際のゲームコードと Three.js の計算処理を実行した。DOM・GPU・音声出力は代替実装のため、実際のブラウザ操作、映像、音質、FPSを検証した結果ではない。以前のブラウザ操作の安全ポリシー拒否を回避する経路は使用していない。

## 性能

60fps相当の更新処理を停止・歩行・飛行それぞれ1,800フレーム実行し、最初の300を除く1,500回を集計。実際の移動計算・カメラ衝突・エフェクト更新・シーン座標変換を含む。移動は同じ区間を反復した。WebGLRenderer は代替実装で、GPU送信・影描画・シェーダー・DOM描画は含まない。

| 状態 | CPU時間中央値 | 95パーセンタイル |
|---|---:|---:|
| 停止 | 0.314ms | 0.372ms |
| 歩行 | 0.317ms | 0.378ms |
| 飛行 | 0.278ms | 0.322ms |

今回の環境では計算処理自体は軽い。ただし、この数値からブラウザのFPSは推定できない。

シーン全体の静的集計（非表示の簡易建物を除く、画面外も含む）：

- メッシュ描画単位：1,098。雲のスプライト：160。エフェクト：2。
- 三角形：約47.6万。影を落とすメッシュ：996。
- 追加の小物は69個を7バッチに集約できている。移動エフェクトは最大128要素に制限されている。

上記は実際の1フレームの描画回数ではない。画面外除外で減り、影の描画で追加される。描画単位の多さと動的な影は負荷の候補。質感や小物を減らす前に、橋の板・木などの同形状をまとめ、影の対象を絞ることを検討する。効果は実GPU計測で判断する。

## 合格した検査

- 全方向移動、通常のマウス移動で視点が回らないこと、左・右ドラッグと解除、加減速、滑らかな旋回、飛行の上昇・下降。
- 家屋の壁、階段、橋面の高さ、最高速度での家屋の壁抜け防止、30/60/120Hz相当の更新における移動距離の一致。
- 実GLBの解析、9棟の配置、材質へのテクスチャ参照とUV、小物の数・描画予算。
- 音の開始・消音・音量・停止再開・発音数制限・解放のロジック。
- 歩行・飛行・停止・着地時のエフェクト、要素数上限、座標の正常性、無効化、カメラを変更しないこと。

既存の操作テストはDOMイベントの登録先を簡略化している。今回のフォーカス検査は対象タグを指定してキー処理を直接確認したものであり、ブラウザの統合テストの代用にはならない。

## 操作性の追加所見・未確認事項

- Ctrl加速が画面の操作ガイドにない。READMEには記載されている。
- 操作ガイドの文字サイズは9px。小画面での読める大きさや、左下設定との重なりは目視確認が必要。
- タッチ移動・ゲームパッド入力は実装されていない。現状の対象はキーボードとマウス。
- テクスチャ読込失敗の専用表示がなく、質感だけ欠けた場合に原因が伝わらない。
- GPUのFPS・長時間のメモリ推移・テクスチャの見え方・エフェクトのシェーダー動作・音の聞こえ方・カメラ酔いは未確認。

修正順は、主要建造物と橋の衝突 → 設定後の操作復帰 → 低FPS時の時間処理 → GPU実測に基づく描画整理。

検査コマンド（プロジェクトルートから）：`node work/audit-game.mjs`、`node work/test-audio.mjs`、`node work/test-effects.mjs`。追加検査は現状の不具合を再現するassertを含むため、修正後には期待値の更新が必要。

## 追加改修後の再検査

中央島を非対称な輪郭へ変更し、描画形状と歩行可能範囲が一致することを境界座標で確認した。木は枝のある幹と15個の小さな樹冠で構成し、34本を5バッチへ集約した。静的集計は描画単位995、約55.5万三角形、影を落とすメッシュ729。木の形状を増やしながら描画単位と影対象を削減した。

実ブラウザの飛行時は60.0fps、p95 17.6ms、655 calls、約78.6万三角形。自動検査は `node work/test-controls.mjs && node work/audit-game.mjs && node work/test-audio.mjs && node work/test-effects.mjs` がすべて合格した。

## 主人公モデルの再制作

円錐形の胴体と低分割の頭部を、曲面の外套、肩布、顔、髪、帽子、ベルト、鞄、袖、手、靴へ置き換えた。マフラーと髪の交差は実画面で発見して修正済み。操作回帰テストは合格し、安定後の実ブラウザ計測は59.0fps、p95 16.9ms、668 callsだった。

次のアクションは、主人公の品質をさらに上げる場合に限り、Blender製のリグ付きモデルへ移行して手足・外套・マフラーのアニメーションを作ること。現段階の必須修正はない。
